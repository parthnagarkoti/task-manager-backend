# Task Management Backend

A REST API for managing tasks across teams and projects, built with Spring Boot and MySQL. JWT-secured, containerized with Docker, backed by an 8-table relational schema.

## Stack

- Java 17 · Spring Boot 3.2.5 · Maven
- MySQL 8
- Spring Security + JWT (jjwt)
- Docker + Docker Compose

## Getting started

**Prerequisites:** Docker Desktop, JDK 17 (only needed if running outside Docker).

1. Copy `.env.example` to `.env` and fill in real values:
   ```
   cp .env.example .env
   ```
2. Start everything (MySQL + the app) with one command:
   ```
   docker compose up -d
   ```
   The app will be reachable at `http://localhost:8082` (see note below on port choice).
3. Log in with the seeded test user (`src/main/resources/data.sql`) to get a JWT:
   ```
   curl -X POST http://localhost:8082/api/auth/login \
     -H "Content-Type: application/json" \
     -d '{"email":"test@example.com","password":"password123"}'
   ```
4. Use the returned token on the task endpoints:
   ```
   curl http://localhost:8082/api/tasks \
     -H "Authorization: Bearer <token>"
   ```

### Running without Docker

Set `DB_USERNAME`, `DB_PASSWORD`, `JWT_SECRET` as environment variables (matching your `.env`), have a MySQL instance reachable at the URL in `application.properties`, then:
```
./mvnw spring-boot:run
```

### A note on ports

`server.port=8081` and the MySQL host mapping (`3307:3306`) in this repo were chosen because port `8080`/`8081`/`3306` were already in use by other local services during development. If those ports are free on your machine, feel free to simplify them back to the defaults.

## API

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/auth/login` | Authenticate, returns a JWT (prerequisite for the APIs below) |
| `POST` | `/api/tasks` | Create a task under a project |
| `POST` | `/api/tasks/{id}/assign` | Assign a task to a user |
| `PATCH` | `/api/tasks/{id}/status` | Update task status (writes an audit row to `task_status_history`) |
| `GET` | `/api/tasks?status=&priority=&projectId=&page=&size=&sort=` | Filter + paginate tasks |
| `GET` | `/api/tasks/{id}` | Fetch a single task |

All endpoints except `/api/auth/**` require `Authorization: Bearer <token>`.

## Data model

8 tables: `users`, `teams`, `team_members`, `projects`, `tasks`, `subtasks`, `comments`, `task_status_history`. `subtasks`, `comments`, `team_members`, and `task_status_history` are persisted for relational completeness / audit purposes but have no dedicated endpoints — the 5 REST APIs above operate on `tasks`, `projects`, and `users`.

Schema is generated by Hibernate (`ddl-auto=create-drop` — resets on every restart, intentional for this project's scope). `data.sql` seeds two users, a team, and a project so the API is testable immediately after startup.

## Testing

```
./mvnw test
```

Covers `TaskService` (Mockito — happy paths + not-found error cases for all 5 methods) and `TaskRepository`'s dynamic filtering/pagination (`@DataJpaTest` against an in-memory H2 database).

## Scope notes

This project intentionally implements exactly 5 REST endpoints and a minimal JWT setup (login + token validation only — no refresh tokens, no fine-grained role guards). See the implementation plan this was built from for the full list of deliberate omissions (no subtask/comment/team-management endpoints, no Swagger, no environment profile split, etc.).
